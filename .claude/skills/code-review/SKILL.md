# code-review

코드를 수정하지 않고 리뷰 리포트만 출력합니다.
스타일 취향이 아니라 **버그, 회귀, 전시 중단 위험, 누락된 검증**을 봅니다.

## 읽을 문서

변경 파일과 관련된 것만 읽습니다. 읽지 않은 규칙을 근거로 단정하지 않습니다.

| 변경 영역 | 규칙 |
| --- | --- |
| 항상 | `working-rules.md`, `project-constraints.md` |
| 컴포넌트 | `component-guide.md` |
| 상태·전이 | `state-machine.md` |
| 모션 | `motion.md` |
| 에셋 | `assets.md` |
| AI·API | `ai-pipeline.md` |
| 복구·운영 | `operations.md` |

## Workflow

1. `git status --short`, `git diff`, `git diff --staged` 로 범위를 확인합니다.
2. 관련 규칙만 읽습니다.
3. 아래 체크리스트로 훑습니다.
4. 심각도 순으로 보고합니다.

## 이 프로젝트에서 특히 보는 것

**전시 중단 위험**
- 관람객에게 도달하는 에러 UI가 있는가 (폴백이나 `idle` 복귀로 끝나야 함)
- 유휴 타임아웃이 모든 STEP 에서 살아 있는가. `share` 는 180초 이상인가
- 세션 초기화 후 이전 답변·결과가 남는가 (**개인정보 사고**)
- `/api/analyze` 에 rate limit·일일 상한이 있는가

**기기 제약**
- 최신 CSS 를 썼는가 (Chromium 108 기준. `:has()` 가능, nesting·`color-mix()` 불가)
- Tailwind v4 문법이 섞였는가
- hover 를 유일한 어포던스로 썼는가 (터치라 발생하지 않음)
- 터치 타겟이 88px 이상인가
- 디코딩 메모리 예산(300MB)을 넘는 에셋이 추가됐는가
- 풀스크린 Lottie 나 습관적 `will-change` 가 있는가

**컴포넌트**
- 배율을 하드코딩했는가 (`getCanvasScale()` 을 써야 함)
- 색을 하드코딩했는가 (토큰만)
- 절대 위치 요소에 inset 과 `w-full h-full` 을 같이 줬는가 (크기가 깨짐)
- 반복 UI 를 JSX 에 하드코딩했는가 (배열로 선언해야 함)
- 컴포넌트 내부 `useState` 로 선택 상태를 들고 있는가 (세션 스토어가 가져야 함)

**가짜 완료**
- `TODO`, `test.skip`, `.only`, 빈 테스트, 미구현 분기

## 보고 형식

```text
[전시 중단 가능] <파일:줄> <한 문장>
  재현: <조건>
  근거: <규칙 경로>

[관람객 경험 훼손] ...
[개선 권장] ...
```

문제가 없으면 **"없음"이라고 명확히** 적습니다. 억지로 찾아내지 않습니다.

## 하지 않는 것

- 코드 수정 (리뷰 전용)
- 읽지 않은 규칙을 근거로 한 지적
- 검증하지 않은 성능 주장
