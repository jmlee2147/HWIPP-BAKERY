# commit-kr

커밋 메시지만 제안합니다. **`git add` 와 `git commit` 을 직접 실행하지 않습니다.**
이 프로젝트는 사용자가 커밋 시점을 직접 정합니다 (`.claude/rules/commit-convention.md`).

## Workflow

1. `git status --short` 로 변경 파일을 확인합니다.
2. `git diff` 와 `git diff --staged` 를 확인합니다.
3. `.claude/rules/commit-convention.md` 를 읽습니다.
4. 변경 목적을 `feat` / `fix` / `docs` / `style` / `refactor` / `test` / `chore` 로 분류합니다.
5. **목적이 여러 개면 커밋을 나눠 제안합니다.** 독립적인 변경을 한 커밋에 섞지 않습니다.
6. 아래 형식으로 출력합니다.

## Format

```bash
git add <파일...>
git commit -m "<type>: <subject>"
```

여러 커밋이 적합하면 파일 묶음별로 나눕니다.

```text
커밋 1  docs: 작업 규칙 추가
  AGENTS.md, .claude/rules/working-rules.md

커밋 2  feat: Figma 디자인 토큰과 폰트 적용
  app/globals.css, tailwind.config.ts, public/fonts/
```

## 금지

- 이모지
- `Generated by`, `Co-Authored-By` 같은 AI 출처 문구
- 검증하지 않은 변경을 검증한 것처럼 쓰기
- 50자를 넘는 subject
