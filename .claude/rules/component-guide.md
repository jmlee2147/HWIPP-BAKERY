# 컴포넌트 가이드

## 우선순위

1. 시안의 공용 컴포넌트(Figma `1:77707`)에 해당하는 것은 `src/components/common`에 한 번만 만듭니다.
2. 구간 전용 UI는 `src/components/{domain}`에 둡니다.
3. UI 라이브러리는 도입하지 않습니다. 시안이 전부 커스텀 그래픽입니다.

## UI 기본값

- 모든 조작 요소는 터치 기준입니다. 터치 영역은 시안 좌표로 최소 88px을 확보합니다.
- 선택 상태, 눌림 상태를 시안의 상태 변형 프레임대로 구현합니다.
- hover 효과는 보조 수단입니다. 같은 정보가 터치에서도 전달되어야 합니다.
- 텍스트 선택, 길게 눌러 뜨는 메뉴, 이미지 드래그가 체험을 방해하지 않게 합니다.

## 접근성

- 조작 요소는 `button`으로 만듭니다. `div`에 클릭 핸들러를 달지 않습니다.
- 이미지로 된 버튼에는 접근 가능한 이름을 붙입니다.
- 장식 이미지는 `alt=""`로 둡니다.

## 컴포넌트 구조

- `className` prop을 노출해 배치를 바깥에서 정할 수 있게 합니다.
- `className`을 받는 루트 요소에 `relative`, `absolute` 같은 position 클래스를 고정하지 않습니다. Tailwind는 클래스 문자열 순서가 아니라 CSS 선언 순서로 우선순위가 정해져서, 바깥에서 넘긴 `absolute`가 무시됩니다. 안쪽 레이어의 기준이 필요하면 루트 안에 `relative size-full` 래퍼를 둡니다.
- 나머지 props는 `...props`로 전달합니다.
- 시각 상태가 여러 개면 boolean props를 늘리지 않고 하나의 variant 값으로 받습니다.
- 상태는 부모나 store가 관리하고, 컴포넌트는 값과 콜백만 받습니다.

```tsx
interface ChoiceCardProps extends ComponentPropsWithRef<"button"> {
  state: "idle" | "selected" | "dimmed";
}
```

## 반복 UI

문답 선택지, 편집기 탭, 케이크 부품 목록은 `src/data`의 배열로 렌더링합니다. JSX에 항목을 하드코딩하지 않습니다.

## 피해야 할 패턴

- 화면마다 진행 바, 말풍선, 하단 버튼을 복사해 다시 만드는 것
- 컴포넌트 안에서 뷰포트 크기를 읽어 배치를 바꾸는 것
- 하드코딩된 색상 값을 여러 파일에 흩어 놓는 것
