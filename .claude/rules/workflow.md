# 작업 흐름 규칙

## 기본 흐름

1. 현재 구현과 관련 지침을 확인합니다.
2. 가장 작은 검증 가능한 성공 기준을 정의합니다.
3. 작업에 필요한 파일만 수정합니다.
4. 가장 구체적이고 유효한 검증을 실행합니다.
5. 결과, 근거, 남은 공백을 보고합니다.

## 화면 구현 작업

Figma 화면을 구현할 때는 `implement-screen` skill의 순서를 따릅니다.

1. `.claude/rules/figma-workflow.md`에서 대상 노드를 확인합니다.
2. 화면을 정적인 상태로 먼저 완성합니다.
3. 상태 전환과 다음 화면 연결을 붙입니다.
4. 모션은 `.claude/rules/motion.md` 기준으로 마지막에 얹습니다.
5. 시안과 캡처를 비교해 검증합니다.

## Next.js

`AGENTS.md` 상단 안내대로, Next.js API를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 문서를 확인합니다.

## 변경 통제

- 관련 없는 정리는 feature diff에 섞지 않습니다.
- 기존 사용자 변경을 보존합니다.
- 새 추상화보다 삭제와 재사용을 우선합니다.
- 코드 변경은 이슈 → 작업 브랜치 → PR 흐름으로 진행합니다 (`.claude/rules/git-workflow.md`).
- `main`과 `dev`에 직접 커밋하지 않습니다.

## 결정 기록

구조, 라이브러리, 공통 규칙처럼 이후 작업에도 영향을 주는 결정을 내렸다면 `.claude/rules/decisions.md`를 확인하고 필요한 경우 decision 문서를 추가합니다.

- 기존 규칙을 그대로 따르는 단순 구현은 기록하지 않습니다.
- 결정 문서는 근거와 대안을 짧게 남기는 용도이며 작업 로그로 사용하지 않습니다.
