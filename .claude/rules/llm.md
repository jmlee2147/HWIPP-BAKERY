# LLM 호출 규칙

지금은 LLM을 호출하지 않습니다. 케이크 분석은 규칙으로 완성 케이크 예시를 고릅니다(`src/lib/analysis.ts`, 근거는 `.claude/decisions/records/004-cake-analysis-rules.md`). 아래 규칙은 LLM 호출을 다시 넣게 될 때 따릅니다.

## 경계

- 호출은 `src/app/api`의 route handler에서만 합니다. API 키(`ANTHROPIC_API_KEY`)는 서버 환경 변수로만 읽습니다.
- 클라이언트는 `src/lib`의 요청 함수 하나를 통해서만 route handler를 부릅니다.
- SDK 사용법, 모델 id, 파라미터는 기억에 의존하지 않고 구현 시점에 공식 문서로 확인합니다.

## 입력과 출력

- 입력은 문답 답변(관계, 스타일, 파티, 맛 제약)입니다. 자유 입력 텍스트를 받게 되면 길이를 제한합니다.
- 출력은 케이크 구성(크기, 모양, 색상, 장식 id 목록)과 화면에 보일 문구입니다.
- 장식과 색상은 `src/data`에 실제로 있는 id 중에서만 고르게 합니다. 응답은 Zod 스키마로 검증하고, 없는 id는 버립니다.
- 검증을 통과하지 못한 응답을 화면 상태로 쓰지 않습니다.

## 실패 처리

체험이 분석 단계에서 멈추면 안 됩니다.

- 제한 시간을 두고, 초과하거나 오류가 나면 규칙 기반 대체 결과를 씁니다.
- 규칙 기반 대체는 시안 메모의 매핑을 따릅니다: 생일 → 2호, 초, 레터링 / 이벤트 촬영 → 2호, 화려한 장식 / 위로와 응원 → 1호, 레터링 / 일상 → 미니 / 웨딩 → 2호, 레터링, 장식.
- 크기 대응은 2호 = `large`, 1호 = `medium`, 미니 = `mini`입니다. 파티 테마별 조건은 `src/data/analysisRules.ts`에 있습니다.
- 대체 결과를 쓴 경우에도 관람객 화면에는 오류를 보여주지 않습니다.
- 로딩 화면의 진행률은 실제 응답 시간과 무관하게 자연스럽게 흘러야 합니다.

## 남용 방지

- 배포 주소는 공개됩니다. route handler에 요청 크기 제한과 호출 빈도 제한을 둡니다.
