# 검증 규칙

주장을 증명할 수 있는 가장 작은 검증을 선택합니다.

## 명령어 선택

- 문서만 변경한 경우: 변경 파일을 확인하고 build는 생략합니다.
- 좁은 컴포넌트/훅 변경: 관련 테스트가 있으면 실행합니다.
- 공통 유틸리티, store, route handler 변경: 관련 테스트와 `pnpm lint`, `pnpm typecheck`를 실행합니다.
- 앱 전반 변경: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`를 실행합니다.

## 화면 검증

- 화면을 만들거나 고쳤으면 개발 서버를 띄워 1080x1920 뷰포트로 캡처하고 Figma 시안과 비교합니다.
- 휴대폰 크기(예: 390x844)에서도 스테이지가 잘리지 않는지 확인합니다.
- 모션 성능과 터치 동작은 개발 PC에서 확인한 것과 키오스크 실기기에서 확인한 것을 구분해 보고합니다.

## 보고

최종 보고에는 아래 내용을 포함합니다.

- 무엇을 변경했는지
- 무엇을 검증했는지
- 검증하지 못한 항목과 이유

명령어가 환경 또는 의존성 문제로 실패하면 blocker와 다음으로 신뢰할 수 있는 근거를 보고합니다.
