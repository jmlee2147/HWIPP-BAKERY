# StanbyME 2에서 오디오 요소 재생이 불안정함

## 무엇이 다른지

StanbyME 1에서는 효과음과 배경음악이 모두 났습니다. StanbyME 2에서는 배경음악이 나오지 않았고, 카드 뒤집기 효과음처럼 같은 오디오 요소를 되감아 다시 트는 소리는 났다 안 났다 했습니다. m4a 효과음도 가끔은 나므로 AAC 해독 자체는 되는 것으로 봅니다.

## 어디서 확인했는지

- 이슈 #76, 실기기 관찰(카드를 뒤집을 때마다 소리가 났다 안 났다 함)
- 배포 주소의 `/check.html` 소리 항목. 오디오 요소 재생, 요소 11개를 미리 만든 뒤 배경음악, 같은 효과음 되감기, Web Audio 재생을 각각 비교합니다.

## 왜 지금 우리 코드에서 고치면 안 되는지

기기 브라우저가 오디오 요소마다 하드웨어 미디어 자원을 잡는 방식의 차이로 보이며, 우리 코드로 그 동작을 바꿀 수는 없습니다. 대신 `src/lib/sound.ts`에서 효과음과 말소리를 Web Audio로 내고, 오디오 요소는 배경음악 하나만 둡니다. 배경음악은 되감아 다시 틀지 않고 멈출 때마다 새 요소를 만듭니다. 원인은 `/check.html` 실기기 결과로 확정합니다.

반대로 iPhone Safari는 효과음을 Web Audio로 내면 스타일 화면쯤에서 페이지가 종료됩니다(#84, #87). 그래서 Web Audio는 userAgent에 webOS가 있는 기기에서만 쓰고, 그 밖의 기기는 오디오 요소를 미리 만들어 되감아 씁니다. iPhone에서 종료되는 정확한 지점은 확인하지 못했습니다.

## 언제/누가 해결해야 하는지

기기 쪽 동작이라 우리가 해결할 수 없습니다. 효과음을 오디오 요소로 되돌리거나 소리를 미리 여러 개 만들어 두는 변경을 할 때 StanbyME 2 실기기에서 다시 확인합니다.
