# 완성 케이크 예시 검수

완성 케이크 예시 97개를 원형, 하트, 사각형 세 모양으로 바꿨을 때의 모습을 1번부터 검수한 기록입니다. 확인 화면은 개발 서버의 `/dev/cake`입니다.

## 규칙

- 오케이를 받은 케이크는 이후 어떤 변경으로도 모습이 바뀌면 안 됩니다.
- 오케이를 받으면 세 모양의 그려지는 결과를 `src/data/cakePresetsApproved.json`에 저장합니다.
  `APPROVE=cake-01 pnpm vitest run src/data/cakePresets.approved.test.ts`
- `src/data/cakePresets.approved.test.ts`가 저장된 모습과 지금 모습을 비교합니다. 실패하면 오케이를 받은 케이크가 바뀐 것입니다. 공통 규칙(`src/lib/cake.ts`, `src/data/cake.ts`)을 고치지 말고, 고칠 케이크에만 모양별 자리(`at`)나 묶음 이동(`shift`)을 적어 해결합니다.
- 오케이를 받은 케이크를 다시 고쳐야 하면 사용자가 다시 지적한 경우에만 고치고, 고친 뒤 다시 저장합니다.

## 상태

| 상태 | 뜻 |
| --- | --- |
| 오케이 | 검수 통과. 저장되어 잠김 |
| 수정함 | 지적을 받아 고쳤고 다시 검수를 기다림 |
| 지적 | 고칠 내용을 받았고 아직 고치지 않음 |
| 대기 | 아직 검수하지 않음 |

## 공통 규칙을 바꾼 변경

오케이를 받은 케이크가 생긴 뒤에는 아래 같은 공통 변경을 하지 않습니다. 이 세션에서 검수 시작 전에 한 변경입니다.

- 바닥 줄 판정을 장식마다 따짐: 같은 크림으로 윗면 고리와 바닥 줄을 함께 두른 케이크에서 윗면 크림이 사라지던 문제 (`src/lib/cake.ts`의 `inChain`)
- 바닥 줄 크기를 줄 전체의 가운데값 배율로 정함
- 자리가 정해진 장식(레터링, 윗면 크림)에도 예시의 `at`을 적용
- 레터링 비율 수정: `lettering-job-congrats` 원형, `lettering-i-love-u` 하트·사각형, `lettering-happy-birthday-round` 사각형
- 사각형 코팅 3종 3% 확대
- `drops`의 원래 모양 물방울에도 그 모양의 자리(`at`)를 적음. 다른 예시의 물방울 정의를 빌려 쓸 때 원래 모양이 달라도 같은 자리에 놓이게 하려는 것이며, 잠긴 케이크는 그대로임

## 비즈 글자

D+하트 비즈(71개)를 쓰는 cake-70, 93, 94, 99는 어느 모양에서나 비즈를 원래 배치 그대로 평행 이동해 그립니다. `src/data/cakePresets.approved.test.ts`의 "비즈 글자" 테스트가 비즈 간격과 크기를 지킵니다.

## 공유 주소

- 장식을 손대지 않은 완성 케이크 예시는 공유 주소에 장식 대신 예시 id만 담습니다. 공유 페이지가 같은 예시 데이터로 되살립니다. 모양을 바꿔도 300자 안쪽입니다.
- 장식을 고친 케이크는 지금 모양에 쓰는 장식과 자리만 남겨 담습니다(`forCurrentShape`). 모양별 자리는 배열 뒤에 짧게 붙입니다.
- 모양별 회전(`rotate`)을 공유 주소 검증에 넣었습니다. 빠져 있으면 cake-40 사각형을 공유할 때 각도가 사라졌습니다.
