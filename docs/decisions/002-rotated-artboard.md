# 002. 오프닝 아트보드의 90도 회전을 코드에서 변환한다

## 상태

- Accepted (2026-09-21)

## 맥락

Figma `전시 디자인 공유 / 오프닝` 섹션의 컷 프레임은 **세로 화면을 90도 눕혀 그려져 있다.**

- 프레임 안의 좌표계가 **1920×1080 가로**다.
- 자식 노드가 예외 없이 `rotate-90`을 갖는다. 대화박스, 텍스트, 별 하나까지 전부다.
- `get_metadata` 가 프레임을 1080×1920 으로 보고하는 것은 **회전 후 바운딩 박스**다.

`.claude/rules/architecture.md` 는 이런 경우 "임의로 환산하지 말고 디자인 쪽 정리가 먼저"라고
규정한다. 정리를 요청했으나 일정상 코드에서 처리하기로 했다.

공용 컴포넌트 섹션은 회전되어 있지 않다. 오프닝 섹션만의 문제다.

## 결정

Figma 실측값을 **회전 좌표계 그대로** 데이터로 선언하고,
`lib/config/artboard.ts` 의 `fromRotatedArtboard()` 한 곳에서 화면 좌표로 옮긴다.

```
screenLeft = figmaTop
screenTop  = 1920 - figmaLeft - figmaWidth
screenW    = figmaHeight
screenH    = figmaWidth
```

그림자처럼 방향을 가진 값은 `rotateOffset()` 으로 함께 돌린다.

## 근거

검토한 대안은 둘이었다.

| 방안 | 판단 |
| --- | --- |
| 1920×1080 래퍼에 `rotate(-90deg)` | **기각.** 풀스크린 합성 레이어가 한 장 늘어난다. 이 해상도에서 레이어 1장이 약 14MB GPU 텍스처이고, 렌더링이 TV SoC 에서 돈다 |
| 좌표를 손으로 환산해 적기 | **기각.** 반올림 오차가 쌓이고, 디자인이 수정될 때마다 전부 다시 계산해야 한다 |
| **변환 함수 한 곳** | 채택. 합성 레이어가 늘지 않고, 실측값을 그대로 적으므로 추측이 끼어들지 않는다 |

변환식은 컷 2의 두 요소로 검증했고 `lib/config/artboard.test.ts` 에 고정해 두었다.

| 요소 | Figma 실측 | 변환 결과 | 대조 |
| --- | --- | --- | --- |
| 하단 안내문 | L109 T362 W93 H357 | 362 / 1718 / 357×93 | 가로 중심 540.5 ≈ 캔버스 중앙 |
| 대화 박스 | L1538.86 T59 W319.13 H962.44 | 59 / 62.01 / 962.4×319.1 | 좌우 여백 59 / 58.6 |

## 되돌리는 조건

디자인 쪽에서 컷 프레임을 세로로 바로 세우면 **이 변환은 필요 없어진다.**
그때는 `fromRotatedArtboard()` 를 지우고 실측값을 그대로 쓴다.
`features/opening/script.ts` 의 좌표가 전부 이 함수를 거치므로 교체 지점은 한 곳이다.
