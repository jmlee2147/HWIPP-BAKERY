# 모션 기록

`.claude/rules/motion.md` 가 규칙이고, 이 문서는 **토큰을 추가한 근거**만 남긴다.
작업 로그로 쓰지 않는다. 구현 위치는 `components/motion/`, 값은 `variants.ts` 와
`app/globals.css` 의 CSS 변수다.

## 이징 `--ease-pop` (cubic-bezier(0.32, 1.28, 0.6, 1))

컷 1 진입 연출에서 쓴다. 카드·로고·START! 가 목표값을 조금 넘어갔다가 돌아온다.

기존 토큰으로는 대체되지 않는다.

| 토큰 | 끝맺음 | 왜 안 되는가 |
| --- | --- | --- |
| `enter` (out-expo) | 감속해 정착 | 빠르지만 "튀는" 느낌이 없다 |
| `move` (inOut-cubic) | 대칭 가감속 | 부유·순환용이라 등장에 쓰면 밋밋하다 |
| `bounce` | 여러 번 튐 | 등장 요소가 12개라 화면이 시끄럽다 |

제어점 `y1 = 1.28` 은 오버슈트를 약 3% 로 둔 값이다. 넘어갔다는 것이 보이되
튀어 오르지는 않는다 — 전시물이라 하루 종일 반복되므로 과장이 크면 금방 피로해진다.
`1.56`(약 6%)까지 올려 봤으나 화면이 부산스러웠다.

**케이크 탭 반응에는 쓰지 않는다.** 눌린 뒤 되돌아오며 한 번 더 꺾이면 움찔거려
고장처럼 보인다. 그쪽은 `enter` 로 부풀고 `move` 로 가라앉기만 한다.
길게 끌면 이번엔 물렁해 보이므로 440ms 안에 끝내고, 최대치를 앞쪽(22%)에 둬서
손가락에 붙는 느낌을 남긴다. 재생은 CSS 가 아니라
Web Animations API 로 한다 — 같은 카드를 연달아 누를 때 클래스만 다시 붙이면
애니메이션이 처음부터 돌지 않는다. 이징 값은 CSS 변수를 읽어 쓰므로 출처는 하나다.

## 컷 1 타이밍

값은 `components/motion/variants.ts` 에 있다. 순서만 적는다.

```
160ms   카드 6장이 90ms 간격으로 팝인
820ms   로고 네 겹이 함께 낙하
980ms   집게
1320ms  START!
```

카드가 다 앉은 뒤 로고가 떨어지고 마지막에 버튼이 올라온다. 시선이 보드 → 로고 →
버튼으로 한 번만 이동하게 한 순서다.

## 컷 1 → 컷 2 전환

타이틀이 `1.08` 배로 다가오며 걷히고, 그 아래에서 가게 앞이 `0.94` 배에서 다가온다.
두 겹이 **같은 방향**으로 움직여야 화면이 교차되는 게 아니라 안으로 들어가는 것으로 읽힌다.
걷히는 쪽(타이틀)이 위에 있어야 그 연출이 보이므로 겹 순서가 `OpeningScene` 에 고정되어 있다.

길이는 `slow`(700ms) 하나이고 새 토큰을 쓰지 않는다. 끝나는 시점은 타이머가 아니라
`animationend` 로 안다 — 같은 시간을 CSS 와 스크립트 두 곳에 적지 않기 위해서다.
전환 중에는 두 컷이 함께 떠 있으므로 입력을 막는다. 겹쳐 있는 동안의 탭이 다음 컷으로
새어 들어가면 관람객이 컷 하나를 통째로 건너뛴다.

## 컷 1 상시 모션

관람객이 없는 동안 가장 오래 떠 있는 화면이라 정지 구간을 두지 않는다
(`.claude/rules/state-machine.md`).

| 대상 | 주기 | 비고 |
| --- | --- | --- |
| 카드 부유 | 2150~2950ms | 카드마다 주기·진폭·기울기가 모두 다르다 |
| 별판 흐름 | 26px/s | 왕복하지 않는다. 아래 참조 |
| 장식 반짝임 | 2600ms | 420ms 씩 밀어 하나씩 튄다 |
| START! | 900ms | 터치에는 hover 가 없어 상시 움직임이 어포던스다 |
| 하단 안내문 | 1400ms | 글자는 제자리. 번짐만 맥동한다. 아래 참조 |

## 안내문은 움직이지 않는다

"화면을 터치해 들어가기"가 놓이는 자리의 배경 밝기는 224/255 이고 글자는 흰색이다.
대비가 **1.11:1** 이라 밝기를 깜빡여도 읽히지 않는다. 색·폰트·그림자는 Figma 스펙이므로
바꾸지 않았다.

글자를 띄우거나 키우는 안은 버렸다 — 하단 안내문이 오르내리면 화면이 어수선하다.
대신 분홍 번짐(#C12F7D)만 맥동시킨다. 번짐이 강해질 때 윤곽이 드러나 대비에도 도움이 된다.

`text-shadow` 를 직접 애니메이션하면 프레임마다 글자를 다시 그린다. 그래서 번짐이 진한
겹을 글자 뒤에 한 장 깔고 **불투명도만** 움직인다 (`features/opening/TouchHint.tsx`).
그 겹은 0.1 에서 0.5 사이로만 오간다. 꽉 채우면 분홍이 탁해져 글자가 뭉개진다.

이걸로도 부족하면 그때는 디자인 값을 건드려야 한다 — 글자색, 글자 뒤 띠, 그림자 농도.

## 별판은 왕복하지 않는다

CSS 애니메이션으로는 왕복(`alternate`)이나 고정 방향 중 하나뿐이라 "누른 쪽으로 계속
흐르다가 다음에 누르면 그쪽으로 꺾이는" 움직임이 나오지 않는다. 왕복시키면 같은 궤적을
되짚어 빙글빙글 도는 것처럼 보인다.

그래서 `components/motion/useStarFlow.ts` 가 프레임마다 위치를 누적하고 **별 격자 주기로
되감는다.** 되감는 순간의 그림이 같으므로 이음새가 보이지 않고, 그림 크기와 무관하게
무한히 흐른다.

방향은 **포인터가 움직인 방향**이고, 0.3 초쯤에 걸쳐 꺾인다. 포인터가 멈추면 마지막
방향 그대로 계속 흐른다 — 따라다니는 것이 아니라 밀어 준 방향으로 계속 가는 것이다.
2px 미만의 이동은 무시한다. 멈춘 포인터가 1px 씩 떨리면 방향이 계속 흔들린다.
실기에는 커서가 없어 손가락을 끄는 동안에만 방향이 바뀌고, 그 사이에도 흐름은 멈추지 않는다.

주기는 `features/opening/script.ts` 의 `LOGO_STAR_GRID` 다. 원본(966×644)에서 별 중심을
검출해 가로 84.691px · 행 간격 55.065px 을 얻었고, 행이 반 칸씩 엇갈리므로 세로 주기는
그 두 배다. 화면 배치 배율 1.35060 을 곱해 114.384 × 148.744px 이 된다.
**이 값이 틀리면 되감는 순간 무늬가 튄다** — 그림을 다시 받으면 다시 재야 한다.

## `will-change` 를 붙인 단 한 곳

`motion.md` 는 `will-change` 를 습관적으로 붙이지 말라고 한다. 예외는 별판 겹
(`features/opening/TitleLogo.tsx`) 하나뿐이고, 근거는 추측이 아니라 측정이다.

DevTools Rendering → Paint flashing 으로 타이틀 화면을 관찰한 결과:

| 대상 | 결과 |
| --- | --- |
| 케이크 카드 6장 | 초록 없음 — 합성되고 있다. `card-float` 의 `var()` 는 합성을 막지 않는다 |
| 로고 영역 전체 | **상시 초록** — rAF 가 움직이는 별판 겹이 승격되지 않아 형제인 로고 판·글자까지 끌고 다시 그렸다 |
| 대화 박스(타이핑 중) | 초록 — 글자가 정적 필터 안에 있어 글자마다 블러를 다시 계산했다 |

별판 겹에 `will-change: transform` 을 붙이자 로고 영역의 초록이 사라졌다. 비용은 텍스처
한 장(출력 1091×543 ≈ 2.26MB)이고, 그 대가로 블러 필터 둘이 매 프레임 재계산되던 것이 없어졌다.
대화 박스는 글자 겹을 필터 밖으로 빼서 해결했다 — 애니메이션 속성이 `opacity` 뿐이어도
**정적 필터 안쪽이면 비용이 생긴다.**

측정은 DPR 2 조건이었다. 실기 DPR 은 아직 미확인이고(`/debug` 에서 확인), 메모리 숫자는
그만큼 부풀려진 값이다. 어느 요소가 재페인트되는지는 DPR 과 무관하다.
